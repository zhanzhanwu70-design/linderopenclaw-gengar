## 19:30 — DNS-storm analysis: two causes, and one correction accepted

- **Rowlet's IPv6 lead is a red herring — accepted.** `gateway.discord.gg` and `discord.com`
  have **no AAAA records** (so `curl -6` → http=000 just means "no v6 address to connect to");
  only `api.minimax.io` has AAAA (2600:1417:1b::cb45:8ae1) and v6 curl to it works (404).
  → I did **not** apply any `--dns-result-order=ipv4first` change and will not.
- **My independent numbers match rowlet's** (system journal, `getaddrinfo|EAI_AGAIN` per hour):
  00h 105, 01h 802, 02h 236, 03h 86, 04h 13, 07h 312, 08h 60, 09h 269, 10h 101,
  **13h 1130**, 14h 12, 15h 1, 16h 38, 17h 35, 19h 7. Same shape as rowlet's gateway journal.
- **63 "Clock change detected. Flushing caches." events from systemd-resolved today** (01:45,
  02:11–02:36, 03:05–03:13, 05:01–06:17, 07:09–09:39, 10:30, 10:48, 16:47–19:25).
  Cache Size was **0** during the storm → every lookup went upstream → random failures.
- **BUT: the clock-step theory does not cover the biggest burst.** In the 12:50–14:10 window
  (the one that blacked Discord) there were **0 clock changes** yet 228/271/354/277 EAI_AGAIN per
  10 min. So there are **two independent causes**:
  1. clock step → resolved cache flush → lookups flood upstream (amplifier; explains the
     01h 802, 09h 269, 10h 101 bursts, which do align with flush clusters), and
  2. **genuine upstream-resolver flakiness** (explains 13h 1130 with no flush).
- **Per-resolver reliability measured 19:2x** (10 queries each, 5 s timeout):
  `8.8.8.8` 0 fail · `2001:b000:168::2` 0 fail · `2001:b000:168::1` 2 fail ·
  **`1.1.1.1` 6 fail** · `100.100.100.100` (Tailscale MagicDNS) 10 fail (expected, tailnet-only).
  → The resolver list currently contains 1.1.1.1, which is the *worst* of the reachable ones.
  `resolvectl dns` needs privileges → cannot pin from this lane (owner action).
- **Two concrete remedies for Linder** (both need sudo/owner):
  1. `sudo resolvectl dns wlp0s20f3 8.8.8.8 2001:b000:168::2` — drop 1.1.1.1 (6/10 failures).
  2. Stop the clock stepping (chrony/timesyncd `makestep` → slew only) — fewer cache flushes.
- Rowlet also fixed the self-heal fail-open guard (now fail-closed + 30-min anti-storm) and
  confirmed the dreaming truncation cause: the old guard read `cron list --json` `status`
  (last run status) so it always believed dreaming was idle and restarted mid-run.
