### Lessons
- **Never trust a cron "enabled: true" flag as proof of delivery.** Always check
  `state.lastRunStatus` + `state.lastDeliveryStatus` + `lastRunAtMs`.

  silently kills a daily cron for weeks with no user-visible signal.
- Check `state.consecutiveErrors` proactively, not just on failure.

## Edge-TTS 403 Fix (BBC drill voice was silently degraded)
- The BBC drill run reported "edge-tts returned a 403 handshake error from
  Microsoft's endpoint" — voice fell back to platform native TTS (wrong voice).
- **Root cause**: `node-edge-tts` 1.2.10 used the old endpoint
  `wss://speech.platform.bing.com/.../edge/v1?TrustedClientToken=...` which
  Microsoft now rejects with 403. The Python `edge-tts` 7.2.8 had the same
  problem (also hardcoded `Sec-MS-GEC-Version=1-…`).
- **Fix 1 (Python CLI, used by the BBC cron)**: `pip install --user --upgrade
  edge-tts==7.3.1` → now sends `Sec-MS-GEC-Version=2-…`. Verified: 32KB mp3 produced.
- **Fix 2 (node skill)**: `npm install node-edge-tts@1.2.11` in
  `~/.openclaw/skills/edge-tts/scripts/` → new endpoint
  `wss://api.msedgeservices.com/tts/cognitiveservices/websocket/v1`.
  Verified via `node tts-converter.js --voice en-US-GuyNeural --rate -5%` → 31824 bytes.
- Both paths now work; BBC drill will use the correct en-US-GuyNeural voice again.
- Note: `node-edge-tts` API is `ttsPromise(text, audioPath)` — NOT `ttsToFile()`.
  1.2.11 also changed the WSS endpoint; npm latest is 1.2.11.
