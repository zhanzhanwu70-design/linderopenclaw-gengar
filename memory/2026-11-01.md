### "Discord bot token missing for account 'default'"
- Journal showed `[heartbeat] failed: Discord bot token missing for account "default"`
  at 01:37:01, 02:07:34, 02:33:51 (and `[heartbeat] failed: pending final delivery
  session changed or was deleted` on Oct 31 16:22).
- Root cause: `channels.discord.accounts.default` exists in the config as a **stub with
  no token** (only `groupPolicy` + `streaming`), and `agent:gengar:main`'s session route
  has `channel=discord` but `account_id=None` → the heartbeat delivery resolves the
  account to "default" → no token → the heartbeat run is marked failed (the message
  itself still reaches the user through the normal reply path).
- Note: every agent's main session has `account_id=None`; the other agents' heartbeats
  just skip with `reason=no-route` because their main sessions have `channel=None`.
- Per-agent fix applied: `agents.entries.gengar.heartbeat` =
  `{"every":"30m","target":"last","directPolicy":"allow","accountId":"gengar"}`
  (`heartbeat.accountId` is the documented multi-account selector). Hot-reloaded.
- Rejected alternatives: per-job `--account gengar` on the heartbeat job fails with
  `cron channel delivery config is only supported for sessionTarget="isolated"`;
  giving the `default` account gengar's token would trip OpenClaw's duplicate-token
  gate (`resolveDiscordAccountAvailability` → one of the two accounts gets disabled).
- `openclaw doctor --fix` is the documented sweep for legacy ambient default routing
