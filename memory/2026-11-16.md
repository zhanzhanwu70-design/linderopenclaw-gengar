**Real cause = two independent faults, not a timeout and not contention:**
1. Primary + first fallback both hit the **MiniMax Token Plan cap** (`rate_limit_error`,
   "Token Plan usage limit reached", 2056). Same account (config `minimax.apiKey` ==

   "context window exceeds limit (2013)". M2.7 has a 200k context window vs M3's 1M, and the

   ~1.37 MB payload → M2.7 400 "context window exceeds limit", M3 accepted it (read timeout
   while processing, not a 400).

   the durations are 15 s, not 600 s.**

fallback lists of the isolated crons (`ac9e7ada`, `88810bfe`), whose `lightContext` payloads
