### edge-tts API gotcha (cost ~2 failed runs' worth of time — worth remembering)
- `node-edge-tts` (v?, in `~/.openclaw/skills/edge-tts/scripts/node_modules`) exposes
  **`ttsPromise(text, outputPath)`** on `EdgeTTS`. There is **no `toFile()`** — calling it throws
  `tts.toFile is not a function`. The bundled `tts-converter.js` CLI already wraps this correctly.
- Two more traps when writing a standalone script: (1) `require('node-edge-tts')` resolves from
  **cwd**, so the script must live *inside* `~/.openclaw/skills/edge-tts/scripts/` (next to
  `node_modules/`) or be run from there — a script in `/tmp` fails with `MODULE_NOT_FOUND`;
  (2) inspect the real API surface with
  `node -e "console.log(Object.getOwnPropertyNames(require('node-edge-tts').EdgeTTS.prototype))"`
  before assuming method names.
- **Cheapest path next time:** use the bundled CLI directly, no custom script —
  `cd ~/.openclaw/skills/edge-tts/scripts && node tts-converter.js "<text>" --voice en-US-GuyNeural --rate -5% --output <out.mp3>`.
- Note: `skill_workshop` **cannot** patch this skill — `edge-tts` is `openclaw-managed`
  ("Skill source is not writable by Skill Workshop"), so the gotcha can only live in memory,
  not in the skill file. It is also absent from `references/overview.md`, which documents neither
  `ttsPromise` nor the CLI invocation.
